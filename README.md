## 核心能力

### 1. Agent 编排与运行时

把长链路任务表达成可推进、可交接、可恢复的状态，而不是一串顺序调用。

- 多节点 LLM 有向图编排 + 节点级状态机，支持人工、交接、全自动三种推进方式；交接时携带上下文与未决决策，停滞、超时与终止都能恢复并留审计
- 主笔 / 质检双角色互评改写；按任务类型路由模型，失败自动降到备用模型；不可逆动作前置人工审批门
- 结构化输出用 JSON Schema 加业务规则双重校验，校验不过时把错误结构回写给模型重试，而不是直接抛错终止
- 长上下文按分段边界装配与压缩；在 Cursor / Claude Code / Kilo 之上建团队 Skill 体系并多运行时同步，内部工作流封装成 HTTP / MCP 工具目录供 Agent 调用

### 2. 检索与知识工程

按任务拆检索对象、分块、召回、重排与记忆写回，效果可度量、可回归。

- 多模态检索：图像抽结构化属性 → 查询归一化 → 标量预过滤 → pgvector 向量召回 → 重排精排
- 文档按行号规范双轨切分入库，检索结果可回指原文位置；该能力作为生产 API 被下游固定调用
- 已完成产物抽取成实体 / 场景 / 情节记忆并增量写回，避免每次全量重嵌

### 3. 生产可靠性与效果评测

能证明系统变好还是变坏，能把失败归到模型、检索、工具还是工作流；坏结果进不了生产。

- 可靠投递：任务与投递记录同事务落库（outbox），Worker 用 `SELECT … FOR UPDATE SKIP LOCKED` 竞争取任务，多实例并发下不重复消费也不互相阻塞；心跳超时收割死租约
- 竞态与幂等：唯一键冲突走"捕获后复用已有行"，消费标记改 CAS，失败分支先探测在途任务，避免并发双方互相撤销对方的资源占用；分布式锁用 Lua 脚本比对持有者后再释放
- 护栏：内容合规过滤与画面质检卡在不可逆节点；回归用例进发版门禁；节点探测失败自动摘流
- 失败归因分模型 / 检索 / 工具 / 工作流四类，线上与压测故障按根因归档成判定清单与处置顺序，要求按根因修复而不是按单个任务打补丁

- **数据建模：** 按"标量预过滤 + 向量召回 + 精排"三段设计——1024 维向量列建 HNSW（余弦距离），风格 / 性别 / 年代建 B-tree 供先验过滤，避免全库向量扫描；召回 Top50 后交重排模型精排
- **评测：** 自建 92 case 人工标注 golden 集，分主体类型统计、逐题归因。Top5 命中率 74.7%（68 / 91 个有标注用例至少命中一个标注资产。此口径不是 recall@5——同一份逐题表的 mean recall@3 / @5 为 0.346 / 0.518，分母取 `min(标注数, K)`，未被标注但视觉相似的资产一律计未命中，整体偏保守）
- **由评测定选型：** 横向比 Qwen3-8B、DeepSeek-V3 与纯规则三种查询归一化方案，纯规则在 30 case 选型集上反超两个 LLM，据此把链路定成"规则打底、只有长文本高噪声才调模型"，而非无条件过一遍模型；扩题 30→92 后基线自然下降，未做粉饰而是记录"新增难例使基线更真实"，并定为后续优化的对比基准
