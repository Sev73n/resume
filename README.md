### 1. 检索与记忆工程

### 2. 提示词与结构化控制

提示词是可版本、可校验、可回灌的控制面，不是聊天框里的一段话。

- 按节点拆角色提示词：改编、资产抽取、生图、生视频、口播改稿、15 秒钩子；从剧本抽资产后生成生图提示词并纳入版本流（改编工作台 / 漫剧制作台）
- JSON / Schema 与业务规则校验失败则带着错误结构回写，而不是只报错结束；投放闭环输出结构化字段（投流选片 / 前贴生成）
- 单剧 30–60 万 token 做装配与压缩（长对话按分集边界收敛）；视频提示词和白模 MCP 控制、运镜 Skills 等参考资产按同一套约束出（改编 / 分镜参考）



### 3. Agent 编排与多智能体

自研业务状态、交接协议和人工卡点，换模型、换画布不必先迁一套框架。短任务脚本化，长链路交给模型，人只卡不可逆节点。

- 改编流水线 10 步、16 个 LLM 节点，按节点状态机推进，支持手动 / 交接 / 自动巡航；Handoff 带走上下文和未决决策，stuck 与终止可恢复、可审计（出海剧本改编）
- 双角色主笔 / 质检做 critique-revise；React 制作台 / 审核后台独立交付，节点状态直接打到画布；抽取、改编、出片按任务分模型（改编 / 漫剧制作台）
- 在 Claude Code / Cursor / Kilo 等 Agent Runtime 上建设 30+ 团队 Skill，多运行时同步；内部工作流经 HTTP / MCP 目录供 Agent 检索调用。编码 Agent 只加速协议与技能，不作为线上 Runtime（团队编码 Agent）



### 4. 知识资产生命周期

把剧本、成片、人设和图像从文件变成可检索、可约束生成的设定层，并支持增量更新。

- 剧本 docx 经行号规范、双轨切分进入向量库；成片 / 漫画可转入人物、场景、情节记忆，供改编和套拍回查（剧本中台 / 视听转写）
- 人设、人物图、场景与道具抽取后入库；人物库本机对象存储主读写，公网图双写云存储（人物资产 / 漫剧资产）
- 共用对象存储承载素材、成片与知识库文件约 1.2T；新设定增量写回，避免每次全量重嵌（内网对象存储）



### 5. Agent 运行时与全栈底座

Agent 是带租约、选路、回落和长事务的服务；内网把原型、任务、模型和存储收成可调用底座。

- 收口工作流原型、异步任务运行时、模型网关；统筹内网 Git 内容管理与团队 skills 技术沉淀统一入口，并做跨地域解析。短任务走工作流运行时，长任务走 GPU 租约；网关按任务类型选模，失败可切备用模型（内网 Agent 底座）
- 控制面拆两层：任务进队列，按进行中任务数选 Worker；GPU 网关 Reserve → Execute → Release，失败换机最多 3 次。跨服务、过人工卡点的长任务用工作流引擎接着跑（媒体算力调度）
- 生产 / 测试域名分开，Git + Compose 发版；转写按文件指纹缓存，热数据走 Redis；坏机器隔离后再接活。成片和素材先落本机对象存储，对外交付走云存储，必要时换备用云（投流 / 算力 / 资产）



### 6. 评估、护栏与生产闭环

能证明 Agent 变好还是变差，并把失败归到模型、检索、工具或工作流；坏结果进不了生产。

- 检索有 golden 与 recall@k；切分回归进生产；投流发版走门禁（r1–r110）。失败能回看卡在哪一步：选片胡切、检索没命中、还是调度把机器租死（人物检索 / 切分 API / 投流成片）
- 选片与改编用模型互评 + Schema / 业务校验回灌；内容红线、黑场 / 短镜头等质检卡在不可逆节点（改编 / 投流 / 制作台）
- 任务先落库再投递（可靠投递），媒体队列按项目建模，库锁抢活避免双投；看门狗收回死租约；导演 / 制片 / 投放审核未通过，成片不进分发或投放（投流 / 数字人口播）



### 7. 通道、工具与第三方接入

制作和投放的人已经在钉钉 / 飞书 / 微信里干活，Agent 接到这些会话里，工具按需调用，而不是再做一个聊天站。

- 接入 OpenClaw（不自研 Runtime），打通钉钉 / 飞书 / 微信 / Telegram：双向收发、多轮会话，会话接到内部工具目录（多 IM 通道）
- 业务侧钉钉 / 飞书继续做排期、审批和群通知，和制作知识库对着，不是只推一条消息（制作协同）
- 工具目录里有元搜索、网页抓取和模型网关；工作台流程和 IM 会话用同一套工具，按 Tool Calling 调用（搜索 / 浏览 / 模型调度）
