03

核心能力

01 需求洞察与分析

跟岗观察、用户访谈 → 需求拆解 → PRD → 需求评审与排期 → 验收标准 → 上线后数据复盘。直接对接过编剧、导演 / 制片、原画与设计师、投放运营、业务负责人、外部模型厂商，以及企业负责人、政府部门与宣发部门。

02 AI 产品设计

  • 人机协作：设计人工、交接、全自动三种推进模式；只在不可逆节点前保留人工审批，任一节点都可以打断、修改后交回模型继续。
  • 过程透明：用节点画布与实时流式输出展示 AI 每一步在做什么，节点状态分为待执行、执行中、待人审、成功、失败可恢复，让用户放心把工作交给 AI。
  • 把经验变成产品：把编剧、编辑、投放人员的经验拆成节点规则、质检清单和提示词，让新人和模型都能照着执行。
  • 效果评测：用人工标注的 Golden 集、LLM-as-a-Judge 分维度打分和灰度 A/B 验证效果，指标不退化才全量上线。

03 平台化与产品矩阵

识别多条产线的共性需求，把模型、算力、检索、审批、计费沉淀成共享能力；一个产品验证过的能力（如人物资产检索）直接复用到其他产品。

04 规则、合规与质量治理

把依赖人工的审核规则固化为产品流程（节点审批、结构化校验、质检清单、发版门禁）；上游设内容验收与审核红线，自动打码与画面质检放在不可逆节点之前；敏感数据只走本地模型。做过按商品、时段和用户身份分层的动态定价与优惠推荐规则。

05 商业化与成本意识

  • 单位成本模型：按单任务成本、每分钟成片成本、单条素材成本衡量产品价值，用来决定需求优先级和方案取舍。
  • 计费产品：多用户 SaaS 计费与运营后台；额度按「预占 → 成功扣费 → 失败释放」三段式结算，避免任务失败时多扣或漏扣。
  • 降本：统一模型网关、本地推理分流与供应商比价，模型调用综合成本降低 30%+。

06 生态合作与跨团队协作

与火山引擎研发（Seedance 2.0）、Vidu 等模型方配合调参，把模型能力的升级转化为产品形态的升级；对接外部模型厂商谈渠道、配额与价格；带过约 10 人的研发团队。新闻采编与商业企划出身，写过技术方案书、投标文件和政府项目立项、验收材料。

07 AI 工具与 Agent 搭建

Dify、LangChain 快速原型；团队 30+ Skill（同步到 Cursor 与 Claude Code）；把 Dify 工作流封装成 API 目录供 Agent 调用；接入 OpenClaw，让 Agent 进入钉钉、飞书、企业微信；熟悉 MCP 工具调用和 RAG 检索。

    • 全链路节点化：「创意 → 辅助创作 → 剧本拆解 → 人物设定 → 角色设计 → 资产生成 → 分镜 → 视频生成 → 验收审计」，每个节点都有明确的输入、输出和验收规则。
    • 辅助创作工作台：多用户界面，提供文稿自动分析、剧本辅助创作、AI 分镜、镜头设计辅助、角色资产出图与视频生成。
    • 可视化编排画布：制作人员在画布上看到每个节点的状态和产物，可以随时暂停、替换产物或接管。
    • 3D 导演台：逐场生成三维白模和镜头运动，导演在自动结果上精修机位后导出，作为视频生成的运镜参考。
    • 角色一致性：设计「角色 LoRA + 资产库检索复用」方案，解决跨镜头、跨集角色长相不一致，新项目不必从零建角色。
    • SaaS 化：多用户登录、按用量计费与运营后台，平台可以开放给外部团队使用。
  • 生态合作与迭代：2025.11 起配合 Vidu 调参，先做半自动出片；2026.02 起配合火山引擎研发调 Seedance 2.0，借新模型把默认模式从人工推进改为全自动，只在导演 / 制片验收、审核红线等不可逆节点保留人工。
  • 产品闭环：上游补齐内容验收与审核红线（自动打码、黑场 / 短镜头质检），下游接入投放、二创、人物名贴片与自动配乐，从「做出来」延伸到「能播、能投」。
  • 结果：单剧最小编制由约 100 人降到 3 人，成片成本由行业万元级 / 分钟降到 ¥50–100 / 分钟；单月自动化产出 50 部、5,000+ 分钟；网络大电影《青铜天门之楼兰星骸》获腾讯视频冒险榜 TOP 1，《宗主别撩了：四位尊上要疯了》《钢枪之吻》《诡异降临》《常春藤密室游戏之致命指令》登腾讯火龙漫剧首发榜。

02 营销内容自动化制作与投放平台 2025 下半年 – 至今

技术负责人（兼产品负责人）· 面向 30+ 人投放团队

  • 15,000 条 / 日机器日产能
  • ≈75 人人工日产当量
  • 万元 → 百元级数字人单条成本
  • 164 次4 个月生产发版
  • 业务问题：投放团队靠人工切条、做贴片、拍口播，人均日产约 200 条，素材供给跟不上多平台投放节奏；真人或传统数字人口播单条成本在万元级。
  • 用户与需求：与投放团队对接投放字段、各平台规则与审核规范，把一线反馈和投放数据转成需求优先级。
  • 产品设计：拆成三条产品路径，按制作、审核、批次管理划分多角色工作台。
    • 素材切条：自动理解原片，按投放需要选出高光片段；AI 主笔与质检两个角色按业务清单复核选片，再成片、人工审核。
    • 贴片生成：素材入库 → 转写 → 约 15 秒钩子脚本 → 生成镜头 → 字幕 → 审核 → 合回原片 → 输出投放字段。
    • 数字人口播分发：一句话需求 → 改稿 → 口播脚本 → 配音 → 数字人成片 → 人工审核 → 按账号矩阵分发到视频号、小红书、抖音、大众点评。

关键决策数字人口播的门槛定在哪里

两个选项
一是棚拍加建模师做高精度形象，效果最好，但单条成本万元级、周期长，每次都要依赖外部团队；二是手机手持采集加开源数字人驱动，画质够用，运营可以自助完成。
判断依据
投放素材生命周期短、需求量大、要频繁换人设和话术，决定投放效果的是产量和上新速度，而不是极致画质。
选择与配套
选第二种，把门槛定在「运营自己就能建形象」，只需手机手持拍一段正面说话；形象采集质量不达标就提示重采，不进渲染队列，避免浪费算力。
结果
数字人单条成本由万元级降到百元级，运营不再依赖外部团队建形象。
  • 其他取舍：成片审核通过后才进入分发，某个平台发布失败只在该平台重试，不回滚已过审的成片；按项目隔离队列，避免口播渲染挤占投放素材的产能。
  • 质量与上线：每条路径都在成片后设人工审核；发版前统一过测试、离线质量评测与门禁，按开关灰度上线并备回滚方案。切条产品 2026.05 立项后 4 个月生产发版 164 次，线上问题按根因写正式复盘（4 份），不按单个任务打补丁。
  • 结果：机器日产能 15,000 条，约等于 75 人的人工日产；数字人单条成本由万元级降到百元级；切条路径压测单日成片 1,562 条（约 6,199 分钟），承接 54 个项目，媒体队列零失败。

03 出海剧本改编与剧本中台 2025.06 – 至今

技术负责人（兼产品负责人）

  • 5–15 分钟人工介入 / 任务
  • ¥30–100单任务成本
  • 92 条人工标注评测集
  • 业务问题：把国内剧本改编成海外版本，要同时保证情节忠实、本地化合规和人物一致，过去依赖编辑的个人经验，产能和质量都不稳定。
  • 用户与需求：跟岗观察并访谈编剧与本地化编辑，把改写经验拆成节点规则、质检清单与验收标准，写成 PRD，评审后排期；在日本生活 3 年的经历用于判断目标市场的题材禁忌和人物关系尺度。
  • 产品设计：
    • 改编工作台：10 步 / 16 个 LLM 节点的改写流程，主笔与质检两个 AI 角色互评；提供人工、交接、全自动三种推进模式，编辑可以在任意节点打断、修改后交回模型继续。
    • 视频 / 漫画转剧本：分集转写后合成全剧，自动分析人物、场景与情节，支持视频和漫画两条工作流。
    • 配套能力：多角色 TTS 配音与分镜切割，把「文稿 → 剧本 → 分镜」做成一个工作台。
    • 剧本中台：剧本规范化切分入库、可检索、可回指原文位置，作为下游制作平台固定调用的数据源。
  • 评测驱动决策：自建 92 条人工标注评测集。在查询处理方案的对比中，纯规则方案反超了两个大模型方案，因此把链路定为「规则打底，只在长文本、高噪声时调用模型」，既省成本又更稳定。
  • 结果：单任务人工介入 5–15 分钟（端到端 1.5–3 小时），成本 ¥30–100；人物资产检索 Top5 命中率约 75%，并复用到漫剧制作平台。

04 企业内部 Agent 平台与算力底座 2026.01 – 至今

平台总体规划与架构

  • ≈80%公司模型调用经网关
  • −30%+综合模型成本
  • 30 台GPU 共享调度
  • 业务问题：三条产线各自对接模型和算力，渠道分散、成本不透明，GPU 忙闲不均。
  • 用户与需求：汇总三条产线对模型、算力与工具的共性诉求，收敛成统一的接口与失败处理规则；与外部模型厂商和供应商对接渠道、配额与价格。
  • 产品设计：
    • 统一模型网关：40+ 渠道、OpenAI 兼容接口，按权重、配额和失败自动切换。
    • 算力共享：30 台 GPU 共享调度，渲染与推理错峰使用。
    • 数据安全：敏感数据只走本地模型。
    • 工具目录：业务工具统一注册，Agent 可以直接调用。
    • IM 入口：员工在钉钉、飞书、企业微信里就能和 Agent 多轮对话。
  • 结果：公司约 80% 的模型调用经网关，综合成本降低 30%+。

05 内部 AI 提效工具与 Skill 中心 2026.05 – 至今

体系设计与落地

  • 业务问题：团队经验散落在个人手里，AI 编程工具的规则各写各的；新业务每次都要从鉴权、计费、队列重新搭，上线慢。
  • 产品设计：
    • Skill 中心：沉淀 30+ 团队 Skill，一键安装、双向同步到 Cursor、Claude Code 等多种 AI 编程工具。
    • 工作流目录：把 Dify 上的剧本拆分、分镜、形象、视频生成等工作流封装成 API 目录，Agent 按需检索调用。
    • 一句话出页面：用自然语言生成 HTML 页面，自动发布成内网站点，业务同事不写代码也能做内部工具页。
    • SaaS 应用模板：内置鉴权、计费（预占 → 扣费 → 释放）、任务队列与文件存储，新业务直接基于模板上线。
  • 结果：团队经验与工作流统一沉淀、复用，新业务不必从零搭基础能力。
