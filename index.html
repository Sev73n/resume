  • 工具调用：基于 Function / Tool Calling，把内部工作流、Dify 工作流与第三方 API 封装为 HTTP / MCP Server 工具目录，Agent 按需检索调用；三维白模的机位与运镜规则也经 MCP 工具与 Skill 约束。开发与调试外部 API 插件、沙盒执行环境与自动化执行脚本（营销平台 165 个运维、门禁与任务恢复脚本），熟悉 Function Calling 的深度调试
  • 可靠性与反幻觉：针对模型幻觉与执行不稳定，用工程手段兜底：检索结果作为唯一事实来源并要求引用可回指的原文片段，节点级检查点验证（Temporal 从上一成功步骤续跑）、自纠错机制（Schema 校验失败回写模型重试，主笔 / 质检 critique-revise 迭代打回）、产出可回指原文位置以便核对

  • Streaming 与实时交互：SSE 流式输出与 WebSocket 双向通道，前端实时展示 Agent 每一步的执行过程，人可以中途打断、修改后交回模型继续执行

  • 效果评测：建立 Agent 端到端评估体系：检索侧用人工标注 Golden 集逐题归因；生成侧用 LLM-as-a-Judge 分维度打分（情节忠实度即幻觉率、本地化合规、人物一致性），并定期与人工评审抽样比对一致性；熟悉 RAGAS 等自动化评估指标（faithfulness、answer relevancy、context precision）；持续监测准确率、幻觉率与执行成本，换模型或改提示词先走灰度 A/B，指标不退化再全量
  • 可观测：Langfuse / LangSmith 追踪 LLM 调用链，按节点记录 token、成本、延迟与提示词版本；服务侧接入 OpenTelemetry，熟悉 Prometheus / Grafana 指标告警与 ELK 日志体系；失败按模型、检索、工具、工作流四类归因，按根因修复
  • 可靠性：任务投递用 outbox 模式，Worker 用 SELECT ... FOR UPDATE SKIP LOCKED 竞争取任务，配合幂等写入与分布式锁；内容合规与画面质检设在不可逆节点前，回归用例纳入发版门禁
  • 非功能设计：架构评审必答高可用（多渠道失败切换、超时回收、断点续跑）、成本控制（网关路由、本地推理分流、单任务成本台账）与响应延迟（流式输出、长短任务分队列）三项，按节点监控 token、成本与延迟
  • 权限与安全 rollout：多用户 SaaS 按角色划分制作、审核、批次管理权限，JWT 认证与桌面端单点登录；按项目隔离队列与租约（项目级多租户隔离），避免单个项目挤占公共资源；关键操作全程审计留痕；敏感数据脱敏后才出网，涉密任务只经本地推理；输入侧做 Prompt Injection 防护，输出侧做内容过滤与合规红线（自动打码、画面质检）；新能力按开关灰度上线并配回滚编排
  • 高并发与成本治理：营销平台压测单日成片 1,562 条（约 6,199 分钟）、承接 54 个项目，媒体队列零失败；模型成本通过网关路由、本地推理分流与转写文件指纹缓存治理，综合 Token 成本降低 30%+
